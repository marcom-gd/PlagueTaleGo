PLAGUE TALE GO · THE WORKSHOP

Behaviour Guide

Give your pieces small jobs: move, open a door, spread, or react when someone uses them.

Keep this guide beside your workshop tab. Try one behaviour at a time, then combine them.

The first thing to check: some behaviours need an area to work in. Those belong to a parameter, such as Area of effect or Self, rather than directly to an object.

START SMALL

Make one guard move

  1. In Edit, paint a few connected path nodes. Create a Guard token if you need one, then place it on a node.
  2. Select the Guard in the library. In its inspector, choose Behaviours → Add behaviour → Move To. Set Free nodes per turn to 1 and Move towards to Current Move Target. Save behaviours.
  3. Select the placed Guard on the canvas. In its inspector, choose Set move target → Custom position. Enter the column and row of a free node farther along the path, then set the target.
  4. Choose Playtest → Start turn 1. The Guard takes one step. Next turn takes another; Previous turn goes back.

A target is the destination. Move To is the instruction to travel there. You need both for this example.

WHERE TO PUT IT

Object, state, or parameter?

Token / object
A reusable building block in the library: Guard, Player, Lever… A placement is one copy on the canvas. Editing its shared behaviours changes every copy; a placed piece can have its own state switches and move target.
State
A folder inside a token, such as Alive or Dead. A behaviour placed inside Alive works only while Alive is enabled for that piece. It acts through the placed parent object.
Parameter / effect area
A shape attached to a token: Area of effect, Self, Line Effect, Cone Effect, Rectangle Effect, or Cross Effect. It tells an area behaviour where to look. Self covers only the occupied cell, making it useful for overlaps.

Reusable behaviour blocks

Open Atomic Parameters → Behaviours and use + to create a named block. Filter cards show or hide Parameters, Behaviours, Tags and Tokens; Collapse all / Expand all folds or opens the catalog sections and object branches.

Behaviours use compact colored chips with a small gear icon. In a block’s editor, choose a color preset or use the small + picker for a custom color; the selected choice has an outline. By behaviour type restores the automatic color. The same chips appear in an object’s definition, with nested state-bearing child branches and their parameter logic. Inactive states remain listed as off; child branches without states are omitted. Click the Definition heading to collapse it and make more room for the library.

Drag a behaviour block onto a library item or canvas piece to attach it to that item’s shared definition. You can also select an item, then use the block’s + button. Area behaviours still need a parameter. Click a block to edit it, or choose Edit shared block from an attached behaviour. Changes update every use; incompatible changes are rejected.

In an existing behaviour editor, Save as reusable block creates a block from that behaviour. Choose Save behaviours to link the original item to it. Remove an attachment in the item’s behaviour editor. Deleting a library block keeps its attached logic as independent behaviours.

Adding an area behaviour

  1. Open the library’s Parameters tab and use + to create a shape. For a nearby interaction, try Area of effect with radius 1.
  2. Attach it to the object: drag the parameter onto the object’s library row, or choose that object in the parameter editor’s Nest inside field.
  3. Select the parameter in the hierarchy, then choose Behaviours → Add behaviour. All behaviour types are available there.

Turning Alive off also turns off Use inside Reach. A reusable parameter’s settings and behaviours are shared by every object it is attached to.

“Parent object” in the controls means the placed object carrying that behaviour, including behaviours nested inside its states or parameters.

THE DESTINATION IS NOT THE JOURNEY

Set Move Target, step by step

Think of each piece as carrying a little destination note. Set Move Target rewrites that note. It does not move the piece by itself.

InstructionWhat changes?Example
Set Move TargetThe destination a piece remembers“Guard, head toward that noise.”
Move ToThe piece’s position, a few free nodes at a time“Take one step toward your destination each turn.”
TeleportThe piece’s position in one jump“Arrive at the portal’s destination.”

Example: a noise attracts guards

  1. Attach an Area of effect parameter to a Noise token. Put it where the noise can reach the guards.
  2. On that parameter, add Apply Effect. Choose Eligible objects → Selected object types in area, tick Guard, and choose Action → Set Move Target.
  3. Set Move target → Self (the object carrying this effect). Here, Self means the Noise source. Guards caught by its area remember the Noise source as their destination.
  4. On the Guard token, add Move To → Current Move Target, with 1 free node per turn.
  5. Open Behaviour resolution order in Manipulate & Organize. Put the Noise’s Apply Effect before the Guard’s Move To. Test it with Start turn 1.

The Guard travels along a free, connected path. If the Noise object occupies its destination node, the Guard approaches a neighbouring free node. If there is no available route, it stays put.

The three destination choices

  • Self, inside an effect: the object carrying the effect, such as the Noise source above.
  • Custom position: a fixed column and row. Good for “go to this spot.”
  • Other object in the canvas: a particular placed object. Its current position is followed, so this is useful for chasing a moving Player.

Two other uses of “Self”: the Self parameter means “this occupied cell.” In a placed piece’s own inspector → Set move target, Self means “stay here.” In Teleport’s Object to teleport field, Self means the parent placement.

To check a destination: select the placed Guard and find Move target in its inspector. You can also use Set move target there to give one piece a starting destination by hand.

CONNECT A LEVER TO A DOOR

Finding and using Linked Objects

An object link names a relationship between specific pieces on the canvas. A Lever can be linked to a Door across the room. Creating the link gives behaviours a way to find that Door; you still choose what the behaviour does to it.

  1. In Edit, place a Lever and a Door on the canvas.
  2. Choose Link objects (L) in the canvas toolbar, or press L. Click the Lever and Door to include them.
  3. Click Create link, give it a name such as “Door control,” and save the link.
  4. To find it later, select either piece and look for LINKS near the bottom of its inspector, below the patrol colors. Click the link name to inspect it.

Can’t see the connecting line? Select one linked piece, or turn on Show all parameters with the eye button in the small canvas toolbar. Linking objects is separate from nesting tokens in the library and from connecting path nodes for movement.

Try it: click a lever to open and close its door

  1. Give the Door Closed and Open states. In the Door inspector, enable Mutually exclusive states and turn Closed on.
  2. Attach an Area of effect parameter to the Player. Select that parameter and add Use.
  3. In Usable objects, choose selected object types and tick Lever. In Trigger on, choose Clicked object’s Linked Object(s).
  4. Choose Action → Switch State, select or type Open, and set Switch → Toggle mutually exclusive states. Save behaviours.
  5. In Playtest, move the Player close enough to the Lever. Click its little hand badge: the linked Door opens. Click again to close it. Clicking the Lever’s body still selects it.
Pick Up Parameter only · Interaction

Attach a parameter to any object that can be picked up. Add Pick Up, keep This parameter’s parent object, and choose who can pick it up by object type or tag. Its shape defines the reach. When an eligible collector is nearby, click the item’s ＋ badge. The placement moves into carried inventory and its mini-icon appears beside the collector. You can instead put Pick Up on a collector’s parameter and choose An object in this parameter’s area.

Carry as many separate items as the design needs. Their states remain independent. Click a carried mini-icon to drop that item. Scenery locks, active states, walls, floor heights, and effect blockers constrain pickup. Add Advance Turn On Event to the appropriate actor if pickup should advance a turn; pickup does not add turn rules automatically.

Compose a stick and torch

  1. On Stick’s range parameter, add Pick Up and select the player as the collector.
  2. Under a light source’s active state, add a range parameter with Use. Select the player as usable, set Trigger on → Clicked object’s carried objects, then Apply Effect → Switch State → Torch.
  3. Under Stick’s Torch state, add a parameter with Use → Switch State for nearby objects you want to light. Carried-object parameters follow the collector’s position.
  4. Add Lifetime to the Torch state for the desired duration. Each piece is configured through the normal behaviour editor. No object names or icons imply gameplay rules.

The carried target option also supports Send to Graveyard, Add to Inventory, and Set Move Target. Existing Use selection, state switching, and turn-event rules apply.

Automatic Apply Effect behaviours on carried objects also resolve at the collector’s current position each turn. For example, a lit object’s light parameter can send matching rats to the graveyard. Its Block Node parameters remain passive while carried. States, range, walls, floors, Wait, and the saved resolution order still apply. Carried objects add no extra occupied node; Exclude Self on a carried blocker also excludes its collector.

Lifetime Token, state, or parameter · Countdown

Set Turns before disappearing to X. A temporary object can have Lifetime directly; a state can start it when activated. The countdown appears on the piece or carried icon and in inventory. Each subsequent resolved turn decrements it once; zero removes the object and reports expiry in the log. Wait does not pause a lifetime.

Switching an already-active state, dropping, or picking up an object preserves the countdown. Deactivate and reactivate its state to start a new countdown. Infinite inventory supplies remain templates; copies get independent lifetimes. Previous and saved sequences preserve exact remaining turns.

PICK THE JOB YOU NEED

The seven behaviours

Open a card for the important choices and a small example.

Expand Parameter only · Turn start

“Make more copies here.” Copies the placed parent and its hierarchy onto nodes reachable from its node through connected links within the highlighted area. Gaps, erased connections and floor boundaries stop expansion. Try spreading a rat swarm from a small Area of effect.

Do Not Expand across Stairs is checked by default, including for existing behaviours. Stairs cannot receive or pass expansion while checked. Uncheck it to allow connected routes through stairs between floors.

It normally skips nodes that already contain that object type. Allow copies where this object type is already present permits stacking instead. New copies can run Apply Effect behaviours ordered after Expand this turn; movement, expansion and other actions start next turn. Expansion stops with an error if the level would exceed 1,000 pieces.

Apply Effect Parameter only · Turn start

Choose Eligible objects, then an Action. For Send to Graveyard, Add to Inventory, Flush, or Switch State, choose Selected object types in area to target nested objects by their full path. The area reaches a nested Lantern at its Guard’s cell. A tray transfer removes the Lantern from that Guard’s contents. You can drag the Lantern out of the tray to place it independently.

Block Node Parameter only · Always while active

“These nodes are off limits.” Choose Block for all objects or selected types. Movement only blocks travel; Movement and other effects also makes the nodes act like walls for effects cast by those chosen types, stopping areas on and beyond them.

Exclude Self lets the parent ignore its own blocker. Other copies are still blocked, and other blockers can still affect the parent. Only highlighted cells containing path nodes are blocked.

Example: put the blocker under a Door’s Closed state. Opening that Door disables that blocking branch immediately, without waiting for a turn.

Use Parameter only · Hand click

“Let the player interact with something nearby.” Choose Usable objects, choose Trigger on for the clicked object, its linked objects, or objects with tags, then choose Behaviour to trigger: Apply Effect, Move To, Move Away From, Teleport, Expand, Spawn, or Add to Graveyard / Inventory. Configure the selected behaviour below. Apply Effect applies its Action directly to these targets. Expand uses this parameter’s area centered on each target. Passive blockers and turn events are configured separately. Existing Use actions retain their settings as Apply Effect triggers.

A small hand appears on usable objects in range during Playtest. Click the hand to use; click the body to select. If several actions or stacked usable pieces are available, a choice list appears. Range and active states are checked again when you click.

Use does not run by itself at turn start. Add Advance Turn On Event with Use selected if using something should also take a turn. The lever-and-door example shows the full setup.

Throw Object Parameter only · Throw badge

Choose the Object to throw. Object must be in the player inventory is unticked by default: throws create a fresh copy. Tick it to consume one inventory item per throw, preserving that item’s individual states. Infinite stacks remain infinite.

During Playtest, click the throw badge on the parent object to enter Throwing mode. Hover a node to preview the floating object, a bright destination, and a fainter straight flight path. Click to land inside the parent parameter’s area, including occupied nodes. Throws fly independently of walking connections. Illegal nodes and path portions turn red, and the object becomes transparent; clicking does not throw or consume inventory.

Right Click exits Throwing mode, as the tooltip beside the mouse reminds you. Escape also cancels. Throw Object never runs at turn start. Use Advance Turn On Event with Use selected on the parent if a throw should advance the turn.

Distraction Object, state or parameter · Impact or state change

Distraction movement follows Behaviour resolution order. For a broken lantern to expose a guard to rats before he turns, order Rat Expand → Rat Switch State (Dead) → Guard Distraction → Guard attack. A guard with an active Dead state cancels investigation and return movement, including while his body remains on the board.

Spotlight state changes: attach a separate awareness parameter directly under the Spotlight, outside its directional states. Add Distraction → Trigger → Parent object changes state. Select Spotlight beam parameters for every direction (for example Spotlight Up and Spotlight Right), then select Guard under Object types attracted. This parameter’s shape defines awareness reach; the selected beam parameters define the light. Eligible guards within awareness reach investigate the spotlight when they are outside the new beam, or when the new beam catches them inside after they were outside the previous beam. Guards inside both beams stay calm. The comparison happens immediately for each actual state switch through Use, Apply Effect or On Hit; reapplying an unchanged state does nothing. Movement starts on the next resolved turn and supports the same delays, return and patrol resumption as impact Distraction.

For an impact on a Guard, attach Distraction under its Carry Lantern state. Choose Triggered by thrown objects → Stone, Objects attracted → This object (the object hit), and Attract toward → Thrower’s position at impact. This remembers the thrower’s cell at impact, even if the player moves afterward. Choose speed, delays and optional return. The guard pauses its ordinary movement while investigating. Distraction starts before On Hit switches states and continues after Carry Lantern is disabled.

On the player’s Throw Object, enable Restrict throw targets with condition groups. In an ALL conditions (AND) group, select Guard as the object-type condition and add State is enabled or disabled → Carry Lantern → Enabled. To also allow Pots, click Add alternative target group (OR) and select Pot in that group. This means Pot OR (Guard AND Carry Lantern enabled). Every group is an alternative; within each group, choose ALL (AND) or ANY (OR). Conditions in an AND group must match the same placement. Empty groups and selections match nothing. Missing states never match, including a Disabled condition. Conditions are checked while aiming and again on throwing. Under Carry Lantern, add On Hit → Stone → Switch State → Carry Lantern → Disable to extinguish its nested lantern.

To draw nearby guards to the spot where a lantern broke, add a second Distraction to its range parameter under Carry Lantern → Lantern. Select Objects attracted → Selected objects in parameter area → Guard and Attract toward → Object hit’s position at impact. The destination stays at the impact cell when the lantern guard moves toward the thrower. Both reactions start before On Hit disables the lantern. This fixed position also survives removal of the carrier. Object hit (follow its position) remains available when following a moving object is intended.

Attach this to the Pot’s attraction range. Choose which thrown objects trigger it (such as Stone), which objects are attracted (such as Guard), and nodes per turn. Return to original position afterward is on by default. No separate Move To, state or move target is needed.

While aiming a valid throw at the Pot, its Distraction parameter area and the objects that would react are highlighted. The preview respects the thrown object type, active states, walls and locks. Moving away or cancelling clears the preview.

Delay before approaching sets how many full turns objects wait after impact. Pause before returning sets how many full turns they remain at the destination after arrival. Both default to 0: movement starts on the next resolved turn. For example, a delay of 2 skips the next two turns and movement begins on the third. Normal movement stays paused during both waits. Pause before returning is used only when returning is enabled.

The hit attracts eligible active objects currently in the area. Each remembers its own position and facing. An occupied Pot is approached to an adjacent connected node. The original facing is restored on reaching the starting position; normal movement resumes the following turn. A later distraction restarts the delays and redirects the object while keeping its first return position and facing. Walls, blockers and occupied nodes still constrain movement; locked objects do not react. If the Pot disappears, returning objects head home without waiting.

On the player’s Throw Object behaviour, enable Destroy thrown object on hit to consume the Stone. Enable Restrict throw targets with condition groups and use an object-type condition selecting Pot to reject empty nodes and other objects. Both options are off by default. Impact reactions still run when the Stone is destroyed.

On Hit Token, state or parameter · Thrown impact

Attach On Hit to the receiving object, such as Pot. Choose Hit by thrown objects → Selected object types → Stone, then Action → Switch State and the desired state, such as Broken. Enable, disable, or toggle mutually exclusive states using the same Switch controls as Apply Effect.

The state changes immediately on the object hit. It works even when Destroy thrown object on hit is enabled in Throw Object. Other placements of that object keep their states. A missing state is skipped. You can put On Hit inside a state to react only while that branch is active.

On Hit never runs at turn start. Reactions follow Behaviour resolution order and recheck active branches as they run. Newly enabled On Hit behaviours wait for another impact. Distraction reactions for the impact run before On Hit state changes, so the existing attraction preview still matches the objects distracted.

Move To Token, state or parameter · Turn start

Free nodes per turn sets how many connected, unoccupied nodes a piece can travel. Broken connections, active objects, Block Node, and scenery locks can stop it.

Choose Current Move Target for a destination remembered by the piece. Use Set Move Target or its placement inspector to supply that destination.

For a patrol, choose Patrol · Start first or Patrol · End first, then select a saved patrol or match the piece’s patrol color dot. Ping-pong reverses at each endpoint. To paint a closed route, return to Start from a connected node. In Loop mode, Start first follows the painted order and End first follows the reverse order. An open route uses the shortest free connected path back to the first endpoint.

In Edit token, enable Nodes occupied by this token count as free to let other pieces move through or stop on its node. The box is off by default. Block Node still applies.

Wait Token, state or parameter · Turn start

Choose Turns to wait and place Wait before the actions it should delay in Behaviour resolution order. Set it to 2 to skip later automatic actions for that placement for two turns. On the third turn, those actions can run. Under a state, Wait starts again each time that state becomes active.

Spawn Token, state or parameter · Turn start

“Create another object here.” Choose the library object and 1–100 copies. Each fresh placement appears on the parent’s cell, allowing stacks, with the chosen object’s default states. Spawn can sit directly inside a state such as Dead. A missing or deleted object type does nothing.

New objects begin acting next turn. Later effects in the current turn can still affect them: put Spawn after Flush to keep them out of that flush. The level limit is 1,000 placements; exceeding it preserves the previous state. As a Use trigger, Spawn creates objects at each chosen target’s cell.

Add to Graveyard / Inventory Token, state or parameter · Turn start

Choose Graveyard or Player inventory. This transfers the object carrying the behaviour. A behaviour on a state or parameter transfers the nearest containing object. Matching object types stack in the tray and keep their individual states. When a whole placement leaves the board, links with fewer than two remaining members disappear.

Place this after any actions that the object needs to perform first. Once removed, its later behaviours are skipped. As a Use trigger, this moves the chosen targets into the tray.

Game Over Losing state · When active

Attach Game Over to a character’s losing state, such as Dead. While that state is active, the playtest ends with “Amicia was Go'ed. Clear Sequence to Restart”. Amicia’s active Dead state or entry into the Graveyard is also detected automatically. The turn sequence downloads automatically and Clear sequence blinks to show how to restart. Previous turn remains available to review the ending.

Level Complete Goal object · Overlap

Attach this to an Exit or goal, then choose Object that must be on the owner, for example Amicia. A separate active placement of the selected object must share the owner’s exact cell. Replace older exit effects that send Amicia to the Graveyard with this behaviour. Both manual and automatic movement can trigger it; Advance Turn On Event is optional.

“Amicia is good to GO! Level Complete.” appears and the sequence downloads automatically. Go to next level starts the next level in tab order with its original layout, configured starting inventory, and a new sequence. The final level shows “You GOt through every level!”. Clear sequence restarts the current level. If death and completion happen together, Game Over takes precedence.

Move Away From Token, state or parameter · Turn start

“Keep your distance from a threat.” Set Free nodes per turn (1–100), then select the placed piece and choose Set move target. A custom position acts as a fixed threat; a canvas object is tracked at its current position each turn. Self or a missing object causes no movement.

Each step must increase horizontal-plus-vertical grid distance from the threat. Ties use Up, Right, Down, Left order. The piece stops when no free connected step increases distance, even if a longer detour could escape. Occupied nodes, Block Node, broken connections and scenery locks are respected; Auto-facing follows movement. For example, a Rat with a Torch as its target retreats up to two nodes per turn.

Teleport Token, state or parameter · Turn start

“Jump straight to a destination.” Choose Object to teleport: Self means the parent placement, or select another canvas piece. Then choose a specific column/row, a selected canvas object, or a linked object as the destination.

For Linked object, choose a destination directly linked to the piece being teleported, or leave the choice on the first linked object in saved link order. Arriving in the destination object’s occupied cell is allowed. Missing destinations, walls, out-of-bounds cells, movement blockers, and scenery locks can prevent the jump.

Teleport is also an Action inside Apply Effect and Use. There, the affected objects are the ones teleported.

Advance Turn On Event Token, state or parameter · User action

“This action spends a turn.” Tick one or more events for the parent: Use, Object Moved, Object Added To Inventory, or Object Dropped from Inventory.

Moved includes a successful user drag/drop or arrow-key move. Inventory events include manual backpack collection or placement, and a Use action that adds a target to inventory. Use counts for both the acting parent and the clicked usable object. One user action advances at most one turn, even if it matches several events.

Rotation, failed moves, Graveyard transfers, and initial inventory loading do not spend a turn. Automated turn actions do not start another turn. Previous also undoes the user action that triggered the turn.

WHAT HAPPENS TO THE TARGET?

The Action inside Apply Effect or Use

The behaviour decides when and whom. Its Action decides what happens to the affected object.

ActionPlain-language meaningWhat to choose
Switch State“Become Open, Lit, Dead…”Select a state from suggestions, or type its name to match a state in each affected object. Enable, disable, or toggle its mutually exclusive sibling states. Only that placement changes.
Send to Graveyard“Remove this piece from play.”Choose which objects the behaviour affects. Their individual states are preserved; drag them back from the Graveyard to restore them.
Add to Inventory“Collect these pieces.”Eligible targets leave the board and stack in Player inventory, preserving their individual states. Use Add to Graveyard / Inventory directly on a token or state to collect the parent itself.
Set Move Target“Remember this destination.”Self, a fixed position, or another canvas object. Pair it with Move To → Current Move Target. See the full example.
Flush“Remove this continuous chain.”A caught object starts a chain through horizontally/vertically touching active pieces of the same type, including stacks. Gaps, other types and effect blockers stop it.
Teleport“Move this piece there in one jump.”A specific cell, selected canvas object, or linked destination. No Move To behaviour is needed.

Selecting objects by tag

Object selectors for effects, Use, blockers, move targets, teleport targets and destinations, and overlap colors offer Objects with tags. Match any selected tag on an object or its active contents; tags in inactive states do not match. Placement-specific state switches are respected. An empty selection matches nothing. Filters for objects in an area keep that range. Tagged Use targets and teleport objects select every matching placement on the current level, subject to effect blockers.

When a single destination is needed, move targets and teleport destinations choose the nearest active matching object other than the moving piece. Distance is measured in grid steps; ties use saved placement order. Missing matches cause no movement. Move targets follow the current matches each time the behaviour runs.

Opening and closing with Toggle

For states such as Open and Closed, enable Mutually exclusive states on their parent token. In an Apply Effect or Use → Apply Effect Switch State action, choose Switch → Toggle mutually exclusive states. Repeated applications alternate two states, or cycle a larger sibling group in library order. The chosen state identifies the group and is enabled first if none is active. Non-exclusive groups and single-state groups are skipped.

Choosing Flush reach

Max flush reach → Infinite follows the chain until it ends. Limited counts continuous cells from each initially caught cell, including that cell:

  • 1: only the initially caught cells.
  • 2: those cells plus one adjacent step along the chain.
  • 3: up to two adjacent steps, and so on.

For a line of rats A–B–C, if only A is initially caught, reach 2 removes A and B. A gap before D keeps D safe. Stacked pieces share a cell; each branch follows the same reach limit. Flush works through touching pieces even where there are no path nodes.

Preserving the start of a Flush

Preserve first N cells defaults to 0, keeping existing flushes unchanged. Set 1 to keep all matching objects on each initially caught cell while flushing the chain beyond it. Preserved cells still carry the flush onward; they do not create a gap. Larger values preserve that many continuous cells from the nearest initial catch, on every branch. Distances are counted separately for each object type.

Preserved cells count toward Max flush reach. With A–B–C, only A initially caught, preserve 1 and reach 2 keeps A, removes B, and leaves C outside the reach. If preservation equals or exceeds the reach, nothing is removed. This setting works for Apply Effect, Use Flush, and reusable behaviour blocks.

PUT THE PIECES TOGETHER

Turns, states, and resolution order

Set up behaviours in Edit, save them, then choose Playtest. The board is a private copy. It starts at Ready to start; Start turn 1 runs turn-start actions. Blockers are already live, and Use waits for a hand click.

Open Behaviour resolution order in the collapsible Manipulate & Organize panel, use the canvas ⇅ button, or choose Resolution order in the inspector. Move actions up or down with the arrows.

Order changes the result. A Noise that sets targets before Guards move lets them react that turn. Switching Alive off before a Move To nested inside Alive stops that move. Actions read the states and positions left by earlier actions. Newly expanded copies can run later Apply Effect behaviours this turn; their other actions wait until the next turn.

A rat kills a guard and survives the flush

  1. Give Guard mutually exclusive Alive / Dead states, with Dead initially disabled.
  2. On Rat, attach Self → Apply Effect → Switch State. Choose Guard as the eligible type and enable its Dead state. Self detects a guard sharing the rat’s cell.
  3. Under Guard’s Dead state, attach Self → Apply Effect → Flush, eligible type Rat. Set Preserve first N cells → 1 and keep Max flush reach Infinite to flush the rest of the chain.
  4. Directly on Dead, add Add to Graveyard / Inventory → Graveyard. Remove any Spawn Rat behaviour from Dead.
  5. Set the global resolution order to Switch State → Flush → Graveyard. Start or advance a turn.

Dead becomes active early enough to flush in that same turn. The original attacking rat stays on the guard’s cell, the chain beyond it goes to the Graveyard, then the guard leaves the board. A guard dying without rats creates none. All rats stacked on the preserved cell survive; a later Flush with preservation 0 can still catch them. Moving the guard to the Graveyard last lets it finish flushing.

Move To stops beside an occupied object. Use manual overlap or Teleport for same-cell contact, or replace Rat’s Self with an Area of effect for an adjacent attack. Add Advance Turn On Event → Object Moved to Rat if a manual move should immediately resolve the sequence.

Use Resolution log to see what ran and the affected counts. Previous turn restores positions, states, targets and backpack contents. Save a sequence before leaving Playtest if you want to keep it.

Starting with items? Use Level settings → Player’s starting inventory. Quantity 0 means an unlimited stack. Starting items load before turn 0 and do not trigger Advance Turn On Event. Reset restores them; later manual inventory transfers can spend a turn.

QUICK CHECKS

Something isn’t happening?

“The behaviour isn’t in the list.”
Check the availability table. Select the attached parameter, rather than its parent token, for Expand, Apply Effect, Block Node, or Use.
“My guard has a target but won’t move.”
Add Move To and choose Current Move Target. Check connected free nodes, Block Node, broken connections, and scenery locks. Then start or advance a turn.
“There’s no hand on the lever.”
Use belongs on a parameter. Attach that parameter to the acting object, choose Lever as usable, enter Playtest, and bring the Lever into range. Check enabled states and blockers.
“The lever is in range, but the door doesn’t open.”
Link the placed Lever and Door. In Use, choose Trigger on → Clicked object’s Linked Object(s), then Switch State with an existing Door state.
“Toggle does nothing.”
It is a Use Switch State option. The chosen state needs at least one sibling, and their parent needs Mutually exclusive states enabled.
“Nothing is eligible.”
Tick at least one object type in a selected-types list. A chosen type applies to its placed copies; a selected canvas object means one particular piece.
“A whole branch has stopped.”
An inactive state suppresses all behaviours nested inside it. Inspect the placed piece’s state switches, not just the library defaults.
“The controls disappeared in Projector view.”
Use Show / hide at the top right. Enable Tools or Parameters / Patrols / Resolution Order. Inventory and Graveyard have their own switches.
