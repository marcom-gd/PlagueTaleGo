# Plague Tale GO · Atomic Parameters Workshop

A local web tabletop for teaching game design through atomic parameters. Original pixel sprites, plain-language token rules, and optional turn behaviours for private playtests. Requires **Node.js 20+**; there are no package dependencies and no build step.

## Start on Windows

Double-click **Start Plague Tale GO.cmd**. Your browser opens a welcome page where you choose **Local session** or **Online session**, name your session, and click **Start session**. The workshop opens in another tab; keep the welcome page for your host controls.

Online mode prepares the sharing tool automatically and displays the invitation link, username, and session password. **Copy invitation** copies all three. Participants open the invitation link in their browsers and sign in; the host stays local and does not need to enter a password. **Stop online sharing** disconnects online guests while keeping the local workshop open. Sharing details and passwords are only available on the host's welcome page.

Keep the launcher window running while using the workshop. Double-clicking again reopens the welcome page for the existing launcher. Both old `.cmd` files also open this welcome page. Each new online connection gets a new URL and password; saved projects stay on this computer. Use the same session name to reopen its room. Local sessions are restricted to this computer.

You can also start the launcher from PowerShell:

```powershell
npm start
```

For the original server without the welcome page (including local network access):

```powershell
node server.mjs
```

Open **http://localhost:3000** when running the server directly. A new random room is created for a bare URL. Keep the resulting room link to reopen the same project. To use an explicit classroom room, visit `http://localhost:3000/?room=class-a`. Room names are case-insensitive. The Windows launcher uses a standard Node installation, or the bundled Codex Node runtime when available on this computer.

To change the port:

```powershell
$env:PORT = '3100'
node server.mjs
```

## Workshop workflow

### Clean up unused library items

In Edit mode, open **Project → Clean up unused definitions** to review objects, states, parameters, parameter attachments, reusable behaviours, and tags that no level needs. Click **Remove unused items** to remove the listed items together. **Undo** restores the cleanup.

The review checks every level, including levels hidden from Playtest, starting inventory (including zero-count entries), and references in behaviours and overlap selectors. It keeps complete object hierarchies, disabled states and behaviours, and definitions needed indirectly, such as spawned objects and shared parameters. Levels, placements, notes, and card history are preserved. If someone changes the project during review, review the updated list before applying cleanup. Existing project backups are preserved. Refresh the browser after installing this feature.

### Dedicated User Test sessions

Double-click **Start User Test.cmd**, or run `npm run start:user-test`. This opens a separate launcher (port 3100 by default) with the same Local / Online sharing choices. Prepare and save your design in the normal workshop first, then use the same session name in the User Test launcher. Restart the User Test launcher after changing the design. The editor and User Test launchers can run side by side; invitations from the User Test launcher always open the participant experience.

Participants start in **User Test Mode** in a projector layout with visible level tabs. They may switch to **Sandbox Mode** without resetting the level. Editing and exiting projector view are unavailable. Levels unlock in the saved order; future levels show locks and completed levels turn grey and cannot be reopened. Avatars appear on the tabs where people are playing, with short floating emoji reactions when they select feelings. Cursors are hidden. **Show / hide** still controls inventory, graveyard, and parameter panels.

In **Level settings**, check **Hide from Playtest** to skip a level in the dedicated User Test launcher. It is unchecked by default. Hidden levels stay available in the editor and its normal Playtest modes, and the setting travels with copied and exported levels. New testers see only visible levels, in saved order, with feedback required only for those levels. Existing testers keep their starting snapshot. If every level is hidden, the User Test page explains that no levels are available. Save the design and restart the User Test launcher after changing this setting.

User Test defaults show **Player Inventory** and the **Parameters / Patrols / Resolution Order** toolbar, with **Light** and **Vision** parameter layers checked. Patrol overlays start off and resolution order stays closed. Panel and layer choices are remembered separately from the normal workshop.

In **User Test Mode**, **Replay next turn** only moves forward through turns already recorded by player actions. At the latest recorded turn it is disabled; changing a past state also invalidates its recorded future. **Previous turn** still rewinds normally. **Sandbox Mode** keeps manual turn creation available.

Reaching a configured **Level Complete** outcome first shows the victory popup. Click **Share feedback** to close it and open the required feedback form, including on the last level. Levels without a completion behaviour offer **Finished? Give feedback** for manual completion, followed by the same victory popup and feedback. The form asks for experience (1–5 stars), difficulty (1–5), challenge relative to the rules learned so far (1–10), one or more feelings, friction (or an explicit “Nothing got in my way”), and optional extra thoughts. Feelings include Frustrated, Excited, Eureka!, Surprised, Confused, Good time, Proud, Relaxed, and Bored. The next level opens only after a successful server save. A failed save keeps the form and answers available for retry.

Feedback is saved as readable JSON in **`User Test Feedback/<room>/<tester-id>.json`** on the host computer, separately from project files. Each record includes the nickname/avatar, ratings, emotions, comments, level order, save time, turn count, time on the attempt, and whether Sandbox was used. The file also keeps the starting project snapshot, so changes to the workshop do not change a test already underway. Feedback files are excluded from Git.

Returning in the same browser to the same launcher address and room resumes saved progress. An unfinished level restarts; feedback drafts already opened are recovered from browser storage. Use a separate browser profile or private browsing window for a different tester on the same computer. Clearing browser storage removes that browser’s resume key, but saved feedback remains on disk. A completed test ends with a thank-you screen.

Automated checks: `npm test`. Optional end-to-end Chrome QA: `node tools/verify-user-session.mjs <path-to-playwright/index.mjs>` (requires Playwright and Chrome; screenshots go to `outputs/user-test-check`).

### Shared step guide and timer

The strip below the header follows the class programme: two 90-minute blocks and a ten-minute break. It shows the numbered step and title; click the title for a short, friendly activity reminder. Everyone can open the reminder on their own screen.

Use **‹ / ›** to move the whole room to the previous or next step. Click the timer to **start**, **pause**, or **resume** its allotted time; **↺** restores the full allowance. A completed timer can be restarted. Changing steps loads the new allowance and leaves it stopped. Time reaching zero gives a quiet wrap-up message and keeps the current step visible.

The small tab at the right edge collapses the entire strip and restores it when clicked again. This preference is remembered on your device; the shared timer keeps running while hidden. Controls respond immediately and save changes in order in the background. Timer progress uses a small separate room file (`data/<room>.workshop.json`), avoiding project rewrites and the project editing queue.

The current step and timer are shared across participants, including online sessions, and survive refreshes and server restarts. They are stored separately from the project, so editing, undo, importing a project, and private playtests do not reset them. All room participants can use the controls. The programme’s titles, durations, and participant-facing reminders live in `public/workshop-programme.js`. Restart the server and refresh browsers after changing the programme or installing this feature.

### Placement states and editing tools

Select a placed piece to change its state switches for **that piece only**. Its icon, active tags, and nested parameter overlays follow its own state. Library switches still set shared definition defaults. **Use definition defaults** removes a placement's overrides. Playtest state changes remain private and reset normally.

Active nested objects appear as mini-icons beside their parent piece in Edit and Playtest, using the same badge style as carried inventory. For example, a guard shows its nested lantern while **Carry Lantern** is enabled. Each mini-icon follows that placement's states and disappears when its branch is disabled or removed. State folders and parameters do not get mini-icons. Inventory items carried by the same piece appear alongside these icons and keep their click-to-drop action.

For tokens with several states, enable **Mutually exclusive states (shared definition)** in the inspector to allow at most one sibling state at a time (for example Alive/Dead or Lit/Unlit). Leave it off for combinable states. Nested state groups use their own parent's setting.

**Shift/Ctrl-click** pieces to add or remove them from a selection. The **Manipulate & organize** panel also offers **Select all pieces**, **Clear selection**, **Duplicate selection**, **Lock scenery**, **Unlock**, **Remove selected**. Drag selected pieces or use arrow keys to move the group; **R** rotates selected facing triangles; **Shift+R** rotates selected icons, **Ctrl+D** duplicates, and **Ctrl+C/V** copies/pastes selected pieces. Internal object links are copied when at least two selected members remain in the copied link. Group actions are atomic and use the existing undo system in Edit mode.

Locked placements can still be selected and inspected, but movement, rotation, and deletion are blocked until unlocked. A duplicate selection starts unlocked. With stacked pieces, the inspector's **Objects at this cell** picker selects any piece without moving the ones above it.

Select a library token and choose **Duplicate Selected** to copy that item and its descendants under the same parent, or **Duplicate whole hierarchy** to copy from its top-level ancestor, including sibling branches. Both create independent nested token and state definitions. Attachments to reusable parameters keep their shared definitions. **Level settings → Duplicate level** deep-copies placements, state overrides, locks, object links, and annotations into a new level while retaining references to the shared token definitions. The copy opens in a new tab and uses the current Level settings draft for its name and dimensions; the original level stays unchanged. Master card inventories and draw history remain shared by the project.

The canvas toolbar includes colored **Post-its** and the **Design Experiments** / **Design Challenges** decks. Notes are saved and shared even during private playtests. Each deck starts with 12 prompts and draws randomly without replacement, with independent history per room. Use **Review & edit inventories** to open the host's Card Studio. Master cards live in repository JSON files, while project exports contain notes and drawn-card history. See [Cards and notes](cards/README.md) for editing and usage details. Restart an already-running workshop server after installing this update, then refresh browsers.

1. The library has two tabs: **Objects** shows whole token hierarchies; **Atomic Parameters** contains **Parameters**, **Behaviours**, **Tags**, and **Tokens**. Compact filter buttons share a row with **Collapse all / Expand all**. Toggle filters to include or exclude categories; collapse/expand folds or opens object branches or catalog sections. The library takes most of the sidebar by default. Click **Definition** to collapse its section and give the library more room; this choice is remembered on your device. Click a category’s **+** to create a building block, or use the header **+** to choose what to create.
2. Use **+** in Parameters to create a reusable **Area of effect**, **Line Effect**, **Cone Effect**, **Rectangle Effect**, or **Cross Effect** definition. Adjust its cell range. Drag it onto a token to attach it; the definition stays in Parameters for reuse. Any token can contain other tokens; cycles are prevented.
3. Drag a library token onto a level cell, or click its **+** and then a cell. Its nested parameters come with it. The same definition can be placed many times.
4. Paint floors, walls, and GO path nodes with the left toolbar. Selecting **Floor (F)** expands a sub-panel with **Elevated**, **Ground**, **Underground**, and **Stairs** tiles. Ground is the default for existing maps; the chosen tile stays selected when returning to the floor painter. Nodes sit on top of any floor or stairs tile, preserving the tile beneath them. To connect different floor heights, paint stairs between them and add path nodes with **N**. Adjacent nodes connect automatically in both directions when they share a floor type or either node is on stairs. Bare nodes retain their connections to any floor. Repainting keeps its nodes and erased connections; changing floor heights updates which connections are possible. Walls and Erase Tiles remove both layers. **Erase connection (X)** breaks a link without removing either node; **Reconnect nodes (C)** restores a compatible link. With either tool, click a line (broken links appear dashed) or select two adjacent nodes. Hold and drag to paint tiles. Delete removes the selected piece.
5. Select a placed piece to see its rule, tags, children, and placement notes. Drag to move, press **R** to rotate facing or **Shift+R** to rotate the object 90°, or use arrow keys. Double-click a piece or library token to edit its definition. Definitions update all placements; notes belong to one placement.
6. Use **+** beside the level tabs to add levels. In Edit mode, drag a level tab to reorder it; the insertion marker shows its new position, and holding near either edge scrolls through longer tab lists. You can also focus a tab and press **Alt+Left/Right** to move it. Reordering keeps the current level selected, saves and shares the new order, and supports **Undo/Redo**. Level settings rename, resize, or delete the current level. To shrink a level, first erase tiles and remove pieces beyond the new bounds.
7. Choose **Sandbox Mode** or **User Test Mode** beside **Playtest**, then start your private playtest. Sandbox Mode keeps the existing manual controls. User Test Mode only allows manual moves, rotations, additions, removals, and inventory/graveyard transfers for object definitions with **Can Be Moved in User Test** checked. Moving an existing piece requires one step to an adjacent connected node, even when Snap to Nodes is off; diagonal moves, jumps, and disconnected nodes are rejected. This checkbox is off by default and is available in the object inspector and definition editor in Edit mode; it applies to every placement of that object. Amicia is enabled in the example project. Automated turns and Use behaviours still work for all objects. You can switch modes during a playtest without resetting it. **Playtest** makes a temporary copy in your browser. Move, rotate, duplicate, annotate, or remove pieces manually. Open the backpack toolbar at the canvas's upper left to see the **Player inventory**. Drop objects from the library to add copies, or from the canvas to collect pieces (preserving their states and removing them from the board). Matching objects stack, with their quantity at the icon’s bottom right. Use + / − to adjust a stack; 0 displays as ∞ and supplies unlimited copies. Drag a stack onto the canvas to place one item; placing the last finite item removes that stack. Use × to discard a whole stack. Drop canvas pieces onto the **Graveyard** at the bottom left to remove them from play; expand it to inspect removed pieces or drag one back to restore it. Individual piece states are preserved in both trays. The backpack and graveyard follow you between levels in this playtest. Reset restores the starting layout and configured starting inventory, and empties the graveyard. Returning to Edit discards playtest changes. Other participants keep editing the shared project.
8. **Project** exports/imports JSON, exports an inventory spreadsheet, loads an optional teaching example, or clears the room. Export before replacing an existing project. Imports are validated.

Expand and Spawn now animate new pieces emerging from their origin. Transfers to the inventory or graveyard show the object flying into the tray, followed by a small arrival glow. This includes automatic behaviours, Use actions, and manual collection. Forward turn replay repeats recorded effects; rewinding and resetting clear them. Reduced-motion preferences use an arrival glow without flying pieces. Refresh the browser to load the effects.

### Import and export levels

Use **Project → Export levels** to select one or more levels and download a `.levels.json` file. It includes their maps, pieces, starting inventories, state overrides, locks, links, patrols and notes, plus the objects, states, tags, reusable parameters and behaviour blocks they need. Other levels, the project title and card draw history stay out of the file. Exports use the Edit design, including when opened during a private playtest.

In Edit mode, choose **Project → Import levels**, select a level file, then choose the levels to import. Review missing or different definitions with individual checkboxes or **Select all**. **Inspect definitions** shows incoming and current settings. Objects are selected with their complete nested hierarchy; shared parameters, tags and behaviour blocks have separate choices. Matching definitions are reused. Checked differences are imported as separate variants, preserving current definitions; changed tags receive unique names. Unchecked differences use the current definitions. Unchecked missing definitions omit their pieces, inventory entries and attachments; references are cleared or disabled. The summary reports omitted pieces and inventory entries before you import.

For every matching level name (ignoring case and surrounding spaces), explicitly choose **Make a copy** or **Replace**. Copies receive unique names. Replacements keep the level's tab position. The complete import is one **Undo/Redo** operation. If someone edits the project during review, review the updated choices before retrying.

Behaviour resolution order is shared across the project. The optional **Use incoming behaviour resolution order** checkbox adopts the relative incoming order and can affect existing levels; otherwise the current order stays first and new behaviours are appended in their exported order. Include related levels together when behaviours target objects or patrols in other levels; the review warns about unavailable targets. Level files are limited to 2 MB, and existing project limits still apply (30 levels, 500 library items). Restart an already-running server and refresh the browser to enable importing.

Tags have a **name**, **rule / description**, and **color**. Create or edit them in the Tags tab, then reuse the same tag in multiple tokens. In the token editor, type in the tag search to attach an existing tag or choose **Create** to define and attach a new one without leaving the editor. Click an attached tag’s × to detach it from that token. You can also drag a tag from its tab onto a library token or a placed piece. Editing a tag updates all uses; deleting it detaches it everywhere. Tags on nested tokens stay with those token definitions. Existing projects and imports automatically migrate text labels into reusable tags.

In a token or state editor, search **Parameters** to attach an existing definition, or choose **Create** to open the parameter editor and return with it attached. Changes to its shape, range, rule, tags, color, and behavior update every use. Detaching a use or deleting its owner keeps the definition available; deleting the definition removes all its uses.

Closing an editor with unsaved changes offers **Save changes**, **Discard changes**, or **Keep editing**. This applies to tokens, parameters, states, tags, object links, post-its, and level settings, including Cancel, Escape, and clicks outside the editor. Drag the **Objects** or **Atomic Parameters** tab out of the sidebar to float that view independently. Drag **Definition** by its heading to float it too. Move floating panels by their title bars and resize them from the bottom-right corner. Drag a panel back onto its sidebar docking area, click its **↙ Dock** button, or use **↙ Dock all floating panels** in the library header. Searches remain independent and all views stay live. Floating positions and sizes are remembered on your device. **Alt+Enter** on a tab or heading toggles docking; **Alt+arrow keys** move a focused floating title bar.

In Definition’s **Behaviours** hierarchy, drag a behaviour to move it between branches, or drop before/after another chip to reorder it. Empty states provide drop areas, including disabled states. Drag reusable blocks from **Atomic Parameters → Behaviours** onto these areas to attach them. Moves preserve shared behaviour links, update resolution order, and support Undo/Redo. Shared parameter edits apply to every use, and incompatible destinations or duplicate shared blocks are rejected. Behaviour dragging is available in Edit mode. Restart the Workshop server and refresh the browser after installing this update.

Use **Nest inside** in an editor (or drag in Objects/All) to put sub-tokens and parameters under that state. State folders must belong to a token or another state and cannot be placed independently.

Existing v1 and v2 projects migrate without changing their saved hierarchy, tags, placements, or broken connections.

The workshop opens in **Light mode**, with cream panels, beige floor tiles, and blue selection accents. Use **Dark mode / Light mode** in the header to switch. Your choice is remembered on this device and does not change anyone else's view.

### Visual parameters

Assign a **Parameter Layer** in the parameter editor: **Light**, **Vision**, **Range**, or **Other**. Existing parameters default to Other. The layer belongs to the reusable definition, so edits update every attachment. Open the eye button’s **Parameter layers** menu and tick the layers to show across the board. These checkboxes are remembered on your device and work in Edit and Playtest. Selecting a token still previews all its active parameters.

Parameters are occluded at changes between Elevated, Ground, and Underground floors, independently of **Occluded by Walls**. A straight effect line can cross heights through **Stairs**; stairs elsewhere do not let an effect bend around a floor boundary. Floor boundaries also block diagonal corner leaks. Empty cells, bare nodes, and walls retain the last floor height along the line (Ground at an unpainted origin). Overlap colors and parameter behaviours use the same clipped area; layer visibility only changes the display.

**Self** covers only the token's occupied cell. Use it to detect overlapping objects or apply effects to them during playtest. It supports reusable attachments, state gating, overlap object filters and overlap colors like other parameters. Its area stays one cell regardless of range, rotation, facing or wall occlusion; the range slider is hidden for Self.

**Cross Effect** draws a + centered on the token, including its cell. Arm length controls how many cells each of its four one-cell-wide arms reaches. It supports wall occlusion and overlap coloring like other parameters.

Use **Link objects (L)** in the canvas toolbar to connect two or more placed objects. Click each object to include or remove it, then **Create link**. Give the link a name, rule / description, and color; the editor also lets you change its members. Semi-transparent lines follow the objects as they move. The name label appears when any member is selected or any parameter layer is checked. Click the label (or a link in a placed object's inspector) to inspect, edit, or **Delete link**. Delete/Backspace also removes a selected link. Links are saved with the level and included in exports and undo history. Removing a member keeps links with at least two remaining objects; smaller links are removed automatically. State rows show their chosen icon and variant.

Area of effect uses Manhattan distance: a **diamond** of grid cells around the placement. Line of sight is a **straight line** in its facing direction (up at 0°, right at 90°). Selecting a piece shows its own and all nested overlays. The eye menu shows checked parameter layers for every placed token. Color and range belong to definitions; rotation belongs to placements.

Overlays are visual rulers and define the cells used by effect behaviours. Enable **Occluded by Walls** to clip an effect. Without assigned behaviours, play remains manual. You can move and stack objects by hand, respecting active Block Node rules; automated movement uses connected, free path nodes. Children travel as parameter definitions, not additional movable pieces.

### Playtest turns and behaviours

For a student-friendly walkthrough, open the **Behaviour Guide** from the Field guide’s **Assign behaviours** section or the behaviour editor. It opens in a separate tab and covers where to attach each behaviour, Set Move Target, Linked Objects, worked examples and troubleshooting. The standalone page is served at `/behaviour-guide.html` ([source](public/behaviour-guide.html)).

Select a token, state, or parameter in Edit mode and choose **Behaviours** in its inspector. **Move To**, **Move Away From**, **Spawn**, **Add to Graveyard / Inventory**, **Teleport**, and **Advance Turn On Event** can be assigned to any of these; **Expand**, **Apply Effect**, **Block Node**, and **Use** belong to an effect parameter. Parameter behaviours are shared by all attached uses. Place an effect under a state to gate it: inactive states and all their descendants do not act. A behaviour assigned to a state acts on the placed parent object while that state is active.

The horizontal toolbar appears in **Playtest**. **Start turn 1** resolves the first turn; **Next turn** resolves another. **Previous turn** restores the previous snapshot, including every level, object position, individual state, current move target, patrol direction, inventory, and graveyard. Next replays an existing future snapshot; changing pieces or settings after going back discards that future and resolves a new branch. Manual changes are captured when you navigate or save. Turn 0 is the layout before the first turn.

**Save sequence** downloads a separate JSON file containing all turn snapshots and the current position in the sequence. **Load sequence** validates and replaces your private playtest with that file, including its object definitions; it does not import it into the shared design. **Clear sequence** (or Reset) restores the starting layout, starting inventory and starting level, and returns to turn 0. Loaded sequences reset to their initial snapshot's trays. Sequences support 200 turns and imports up to 50 MB. Save before leaving Playtest or refreshing. Notes and design cards remain shared room observations and are not rewound or imported by turn playback.

In **Level settings → Player’s starting inventory**, add object types and quantities. **0 = ∞** gives an unlimited stack. Playtest starts with the selected level's configured backpack, including definition-default states; changing level tabs keeps that backpack. Starting items are created directly before turn 0, without collection or drop events, so **Advance Turn On Event** never advances a turn during initialization or reset. Later manual collection and drops still trigger their configured events. The settings save with the level, survive project export/import, and are included when duplicating a level, including the current unsaved inventory draft. Deleting an object definition removes it from starting inventories. Up to 1,000 initial items are supported, counting an infinite stack as one; existing projects start with an empty backpack.

- **Expand:** at turn start, duplicate the placed object with its hierarchy, state overrides and placement properties onto path nodes reachable from its node through connected links within the highlighted area. Gaps, erased connections and floor boundaries stop expansion. **Do Not Expand across Stairs** is on by default, including for existing behaviours: stairs cannot receive or pass expansion. Uncheck it to allow connected routes through stairs between floors. By default, skip nodes already containing the same object type. An optional stacking switch allows additional copies. New copies can run Apply Effect behaviours ordered after Expand in the same turn, so a rat entering a guard’s cell can kill immediately. Their movement, expansion and other actions start next turn. The 1,000 placements per level limit still applies; a turn exceeding it leaves the previous state intact.
- **Apply Effect:** choose eligible library object types (an empty selected list affects nothing), Any object type, or **Linked Object(s)**. Area targets use the effect's current shape, rotation, facing and wall occlusion; Linked Object(s) affects direct link members outside the range as well, respecting effect blockers and optional wall occlusion. The source and effect markers are excluded. Choose **Switch State**, **Send to Graveyard**, **Add to Inventory**, **Set Move Target**, **Flush**, or **Teleport**.
- **Block Node:** while its state is active, nodes inside the effect area block **All objects** or selected object types. **Movement only** restricts automated movement, manual dragging, arrow-key movement, and inventory placement. Manual movement between nodes must have a connected route around the blockers. **Movement and other effects** also makes those nodes act like walls for effects cast by the chosen object types, stopping affected cells on and beyond the blockers. Enable **Exclude Self** to exempt only the parent placement from its own blocker, for both movement and effects; other copies of the same object type remain blocked, and other blockers still affect the parent. Existing blockers keep Exclude Self off. Blockers follow their owners and state changes immediately; they do not wait for a new turn. Blocker areas use their own geometry and wall settings directly, avoiding circular dependencies between blockers.
- **Use:** choose usable objects by type or tag, select the clicked object, its linked objects, or tagged objects as targets, then choose **Behaviour to trigger**: **Apply Effect**, **Move To**, **Move Away From**, **Teleport**, **Expand**, **Spawn**, or **Add to Graveyard / Inventory**. Configure that behaviour below the chooser. It runs once on each target when clicked. Apply Effect applies its Action directly to the chosen targets; Expand uses the carrying parameter’s geometry centered on each target. Passive Block Node and Advance Turn On Event remain separate. Existing Use actions load as Apply Effect triggers. During Playtest a small hand badge appears at the corner of each usable object in range, leaving the object itself selectable. Click the hand to run the chosen behaviour. If several uses are available, choose one from a short list. Range, states, wall occlusion, and effect blockers are checked again when clicked. Use actions do not run automatically at turn start.
- **Teleport:** at turn start, teleport **Self** (the parent placement) or a selected canvas object to a specific column/row, a selected canvas object, or an object directly linked to the piece being teleported. Choose a linked destination explicitly or use the first active member in saved link order. The piece may share a destination object's cell. Teleport skips locked pieces, walls, out-of-bounds cells, missing destinations and movement-blocked destinations; it bypasses intermediate path nodes. Teleport is also available as an Apply Effect / Use action. Copied levels remap selected object references to their own copies.
- **Advance Turn On Event:** select any combination of **Use**, **Object Moved**, **Object Added To Inventory**, and **Object Dropped from Inventory**. A successful user drag/drop, arrow-key move, Use action, backpack collection or backpack placement advances one turn if its parent placement listens for that event. A Use is reported to both the acting parent and the clicked object; Use teleporting also reports movement. Groups and actions matching several events still advance only once. Rotation, failed moves and graveyard transfers do not count. Automated turn actions do not recursively start another turn. Previous restores the state before the triggering user action, including inventory transfers.
- **Switch State:** choose an existing state ID from the suggestions, or enter a state name/key to match a state in each target's own hierarchy. Enable or disable it for that piece only. In **Apply Effect** and **Use → Apply Effect**, **Switch → Toggle mutually exclusive states** cycles the selected state's sibling group in saved order: two states alternate on repeated applications. If none is enabled, the selected state is enabled first. Non-exclusive groups and groups with fewer than two states are skipped. Toggle works on every affected placement, preserving definition defaults and other placements. Enabling also enables ancestor states and respects exclusive sibling groups. Objects without that state are skipped.
- **Select by Tag:** eligible effect objects, usable objects, Use targets, Block Node objects, move targets, teleport objects/destinations, and overlap-color filters all offer tag selection. An object matches **any** selected tag on itself or its active descendants, including placement-specific state overrides. Empty selections and deleted tags match nothing. Effect/Use eligibility still respects its area; tagged Use targets and teleport objects select across the current level and still respect effect blockers. Move targets and teleport destinations choose the nearest active matching object, excluding the moving piece, by grid distance; saved placement order breaks ties. Move targets are evaluated again each time the behaviour runs. All other tagged recipient selections affect every matching placement.

- **Send to Graveyard:** remove matching objects in the area, retaining their individual states in the graveyard. With **Selected object types in area**, you can select a nested object by its full path, such as **Guard / Alive / Carry Lantern / Lantern**. The effect reaches the Lantern at the Guard’s cell and removes it from that Guard’s contents. Drag the Lantern out of the graveyard to place it independently. Selected nested objects also work with **Add to Inventory**, **Flush**, and **Switch State**.
- **Set Move Target:** give matching objects a target of **Self** (the object carrying the effect), a custom position, or another specific canvas object. Object targets track their current position. The placement inspector also offers **Set move target** for initial/manual targets; Self there means stay in place.
- **Flush:** start with matching objects caught in the effect, then send each continuous chain of the same object type to the graveyard, even beyond the area. **Max flush reach** defaults to **Infinite**, preserving existing behaviour; choose **Limited** for 1–768 continuous cells. Reach counts from each initially caught cell, including that cell: 1 affects only those initial cells, 2 adds one adjacent step, and so on. Stacked objects share one cell, branches each obey the reach, and multiple seeds use their nearest initial catch. Connections use horizontal/vertical touching cells; they do not require path nodes. Diagonals, gaps, inactive instances, effect-blocked nodes and different object types do not extend a chain. The source is excluded. Only the initial catch uses effect geometry and wall occlusion. **Preserve first N cells** defaults to **0** (existing behaviour). Set **1** to keep all matching objects on each initially caught cell while the flush continues beyond it. Larger values preserve that many continuous cells from the nearest initial catch, independently for each object type and every branch. Preserved cells still propagate the flush and count toward Max flush reach; preservation at or above a limited reach removes nothing. Both settings apply to Apply Effect, Use Flush, and reusable behaviour blocks.
- **Move To:** move up to X free connected path nodes per turn (1–100). **Current Move Target** follows a shortest available path. If another piece blocks the destination, the mover approaches an adjacent free node. In **Edit token**, enable **Nodes occupied by this token count as free** to let other pieces move through or stop on its node. The box is off by default. Movement still respects **Block Node**, broken connections, and scenery locks.
- **Move Away From:** move 1–100 free connected nodes per turn away from the placement’s **Current Move Target**. Set a fixed position or canvas object in **Set move target**; object targets track their current positions. Every step must increase Manhattan grid distance. Ties use Up, Right, Down, Left order; stop when no farther free neighbor exists. Missing targets and Self do nothing. Occupancy, Block Node, broken connections, locks and Auto-facing use the same rules as Move To.
- **Wait:** choose 1–100 turns and put Wait before the actions it should delay in **Behaviour resolution order**. A Wait set to 2 skips that placement’s later automatic actions on the first two turns and lets them run on the third. Put it under a state to restart the countdown each time the state becomes active. Other placements and passive **Block Node** effects keep running.
- **Patrol Start / End:** choose a saved patrol, or match the placement's patrol color dot. Start/End chooses the initial destination. Choose **Patrol mode → Ping-pong** to reverse along the saved route at each endpoint (the default for existing patrols), or **Loop** to follow the route in one direction and take a shortest free connected path back to the initial endpoint. Adjacent connected endpoints close the loop in one step; open routes may retrace nodes to return. An off-route object first travels to the chosen endpoint. Disconnected or occupied route segments stop movement. Patrol progress, including a loop's return path, survives turn navigation, save/load and copies of levels.
- **Spawn:** choose a library object type and 1–100 copies. Create fresh placements at the parent object's cell, allowing stacks and using the chosen definition's default states. This can be attached directly to a state, such as Dead. Spawned objects act from the next turn, but later effects in the current turn can affect them. Missing or deleted object types do nothing. The 1,000 placements per level limit applies; a failed turn preserves the previous state.
- **Add to Graveyard / Inventory:** move the object carrying the behaviour into the chosen tray. A behaviour on a state or parameter moves the nearest containing object. A nested object keeps its individual states when transferred. When a whole placement leaves the board, links with fewer than two remaining members are removed. Put this after any Flush or Spawn that the object needs to perform. This behaviour is also available as a **Use** trigger and reusable block.

Use **Behaviour resolution order** in **Manipulate & Organize**, **⇅** in the canvas tools, or **Resolution order** in the inspector, to rearrange behaviours with ↑ / ↓. Click the **Manipulate & Organize** heading to collapse or expand it; this preference is remembered in your browser. The resolution order is saved with the project and can also be changed privately during Playtest. Turn actions resolve across all levels, top to bottom, then in saved placement order. Distraction movement uses its originating behaviour’s position in this order. Expanded copies join later Apply Effect entries in the same turn. Passive blockers remain live, and Use/event behaviours wait for user input. State activity, positions and eligible objects are checked as each behaviour resolves, so an earlier state change or removal can suppress a later action. The **Resolution log** shows what ran and how many objects or nodes it affected.

**Guard killed by rats:** give the Guard mutually exclusive Alive/Dead states, with Dead initially disabled. On the Rat, attach a **Self** parameter with **Apply Effect → Switch State**, eligible objects **Guard**, state **Dead**, enabled. Under the Guard's Dead state, attach a **Self** parameter with **Apply Effect → Flush**, eligible objects **Rat**, **Preserve first N cells → 1**, and Max flush reach Infinite. Add **Add to Graveyard / Inventory → Graveyard** directly to Dead and remove any Spawn Rat behaviour from Dead. Set the global resolution order to **Switch State → Flush → Graveyard**. An overlapping rat activates Dead; Flush preserves rats on the guard's cell and removes their continuous chain beyond it; the guard then leaves the board. This keeps the original attacking rat, including any rats stacked with it. A guard dying without rats creates none. Move To stops beside occupied objects, so use manual overlap/Teleport for same-cell contact, or an Area of effect instead of Self for an adjacent attack. If movement should trigger the chain immediately, enable **Advance Turn On Event → Object Moved** on the Rat.

**Broken lantern before distraction:** order **Rat Expand → Rat Switch State (Dead) → Guard Distraction → Guard attack**. The throw breaks the lantern immediately, removing its light blockers. Rats expanded into the guard’s cell run their later contact effect that turn. A guard with an active Dead state cancels distraction movement and cannot turn toward the player, even while his body remains on the board. Distraction keeps its resolution order after Carry Lantern is disabled.

Create named **reusable behaviour blocks** in **Atomic Parameters → Behaviours**, or choose **Save as reusable block** on an existing behaviour and then save that item’s behaviours to link it. Drag a block onto a library item or canvas piece to attach it to the shared item definition, or use the block’s **+** with an item selected. Edit a block in the library or through **Edit shared block**; changes update every attachment, including those on reusable parameters. Area behaviours only attach to parameters. Remove an attachment in the item’s behaviour editor. Deleting a block preserves its attached settings as independent behaviours. Blocks and attachments are included in project JSON, sharing, undo and turn history.

Behaviours appear as compact colored chips with a gear icon in the library and definition inspector. In a reusable block’s editor, choose a color preset or use the small **+** picker for a custom color. The selected choice has an outline; **By behaviour type** restores the automatic color. The inspector’s **Behaviours** section shows the selected item’s own chips and a nested summary of child branches with states. Parameter behaviours inside those states remain visible, including inactive branches marked off. Child branches without states are omitted. Click a chip to edit its block or assigned behaviours.

Restart the workshop server and refresh browsers after installing this feature. Existing projects need no conversion; objects without behaviours retain manual play.

### Pickup, carried interactions, and lifetimes

These are separate behaviours that compose through parameters and states:

- **Spotlight investigation:** attach an awareness parameter directly under the Spotlight, outside its directional states. Add **Distraction → Trigger → Parent object changes state**, select all directional **Spotlight beam parameters** (such as Spotlight Up and Spotlight Right), and choose **Guard** under Object types attracted. The awareness parameter defines reaction range independently of the light. On each actual state switch, guards in range investigate if outside the new beam, including guards left outside, or if caught inside after being outside the previous beam. Guards inside both beams do not react. Use, Apply Effect and On Hit switches trigger immediately; setting the same state again does not. Existing investigation speed, waits, return, facing restoration and patrol resumption apply. Restart the Workshop server and refresh the browser to load the new trigger.
- **Throw target groups:** enable **Restrict throw targets with condition groups** on Throw Object. Each group is an alternative (OR). Within each group, choose **ALL conditions (AND)** or **ANY condition (OR)**, then add object-type, active-tag or enabled/disabled-state conditions. Every condition in an AND group must match the same placement; choices within an object/tag row are alternatives. To support both targets with one Stone action, use **Group 1: Selected object types → Pot**, then **Add alternative target group (OR)** and configure **Group 2: ALL → Selected object types → Guard + State → Carry Lantern → Enabled**. Empty groups and empty selections allow no targets. State conditions accept an ID or name, respect ancestors and per-piece overrides, and never match missing states. Preview and impact recheck the same groups; rejected throws consume nothing. Existing type filters and conditions open as one equivalent AND group; unrestricted throws remain unrestricted.
- **Distraction on the object hit:** attach Distraction directly to an object or state and choose **Objects attracted → This object (the object hit)**. Parameters also retain **Selected objects in parameter area**. Choose **Attract toward → Thrower’s position at impact** to remember the thrower's cell when the throw lands; later player movement does not move that destination. Existing **Object hit (follow its position)** remains the default for area distractions. Delays, return, original facing and paused patrols work in both modes. A state-gated distraction starts before On Hit state changes and continues after that state is disabled. For nearby guards investigating a broken lantern, put a second Distraction on the lantern’s range parameter: **Selected objects in parameter area → Guard**, then **Attract toward → Object hit’s position at impact**. These guards remember where the lantern broke while its carrier can move toward the thrower independently. Fixed destinations persist if the carrier disappears; delays, optional return and saved turn history still work.

To break a guard’s starting lantern and make that guard investigate the player’s location: nest Lantern and its light under **Guard → Alive → Carry Lantern**; enable Carry Lantern only on the desired starting placements. On the player’s Throw Object, select **Stone**, enable **Restrict throw targets with condition groups**, and configure an **ALL (AND)** group containing **Selected object types → Guard** and **State is enabled or disabled → Carry Lantern → Enabled**. Add an alternative group containing only **Selected object types → Pot** if that Stone action should also hit Pots. Under Carry Lantern, add **On Hit → Stone → Switch State → Carry Lantern → Disable**, plus **Distraction → Stone → This object (the object hit) → Thrower’s position at impact**. Choose movement speed, delays and whether the guard should return. No additional Move To is needed. Restart the Workshop server and refresh the browser after installing this update.

- **Pick Up** belongs to a parameter. By default, attach it to the pickable object and select **Who can pick it up** by object type or tag. Its shape defines pickup reach. The item shows a **＋** interaction badge when an eligible collector is nearby; clicking moves that exact placement into carried inventory. Alternatively, choose **Object to pick up → An object in this parameter’s area** to put the pickup instruction on a collector’s parameter and select eligible items there. Scenery locks, walls, floors, active states, and effect blockers apply. Multiple objects may be carried; each retains its own state and mini-icon.
- **Use → Trigger on → Clicked object’s carried objects** lets an ordinary effect act on carried items. For example, attach a Use parameter under a source’s lit state, select the player as usable, and choose **Apply Effect → Switch State → Torch**. Nothing in the engine recognizes a light source or a stick by its name or icon. Carried targets also support Send to Graveyard, Add to Inventory, and Set Move Target.
- **Use parameters on a carried object** follow the collector’s position. A parameter under the Torch state can use **Switch State → On** on a nearby brazier. The same system can charge a tool, unlock an object, repair equipment, or apply another state.
- **Automatic behaviours on carried objects** also run from the collector’s current position on each resolved turn. Apply Effect can remove, collect, or change nearby objects; passive Block Node areas follow the carrier for movement and effect checks. Active states, walls, floors, Wait, lifetime, and the saved behaviour order still apply. A collector moved earlier in the turn moves the carried source’s area immediately. Carried objects do not occupy an extra node or move independently of the collector. Exclude Self on a carried blocker also excludes its collector.
- **Lifetime** belongs to any object, state, or parameter. Set **Turns before disappearing** to X. The countdown starts when that branch becomes active, appears on the object and in inventory, and removes the object at zero. It works on the board and in finite inventory, independently of Wait. Disabling its state cancels that countdown; reactivation starts a new one. Reapplying an already-active state, carrying, or dropping an object does not refill it. Infinite inventory supplies are templates; their emitted objects receive their own countdowns.

Pickup and Use follow **Advance Turn On Event** like other interactions. Select Use, Object Added To Inventory, and/or Object Moved on the actor to make those actions advance one turn. No turns or event listeners are added automatically. Previous, saved sequences, and Clear Sequence preserve and restore inventory, target states, and countdowns. Click a carried mini-icon to drop that item.

The saved **plague-tale-go-class-a.json** and **plague-tale-go-torch-demo.json** demonstrate the stick/torch recipe using these ordinary definitions: **Stick / Pick up range → Pick Up**, **lit source / Use carried objects → Use / Switch State**, **Stick / Torch → Lifetime (5 turns)**, and **Stick / Torch / Use on nearby objects → Use / Switch State**. Edit each component in the normal behaviour editor; there is no game-specific setup control.

### Game Over and Level Complete

During Playtest, an active **Dead** state on **Amicia**, or moving her to the Graveyard, shows **“Amicia was Go'ed. Clear Sequence to Restart”**. You can also attach **Game Over** to any losing state, including on renamed characters. The ending automatically downloads the turn sequence, stops further piece actions, and highlights and blinks **Clear sequence**. Reduced-motion settings keep a steady highlight. Clear sequence restores the starting layout; Previous turn lets you inspect and replay the ending.

Attach **Level Complete** to an Exit or goal object, then choose **Object that must be on the owner**, such as Amicia. A separate active placement of that object must share the owner's exact cell. The message is **“Amicia is good to GO! Level Complete.”** and the sequence downloads automatically. **Go to next level** opens the next tab in its saved starting layout, with its configured starting inventory and a fresh sequence. The last level shows **“You GOt through every level!”** instead of a next-level button. Replace older exit effects that send Amicia to the Graveyard with Level Complete. Death takes precedence if both endings occur together.

Endings are checked after manual movement and Use/Throw actions as well as during turn resolution, without requiring Advance Turn On Event. Recorded endings survive Save/Load sequence. Restart the workshop server and refresh browsers to configure the new behaviours.

## Live classroom sharing

Each browser opens a welcome card: choose a nickname, one of seven original 64 × 64 silhouette avatars (Rat, Dog, Cat, Bird, Bathtub Duck, Agent 47, or Lara Croft), and a color. Your previous choices are prefilled on this device. Click your own avatar in the top strip to change them later.

The top strip shows participants in the current room. Colored cursors and nickname tags show where others are pointing on the same level, including across different zoom sizes. **Hide cursors** hides them on your device; use **Show cursors** to restore them. Cursors stay hidden during private playtests and dialogs. Presence is temporary, separate from saved projects, and disconnected participants expire after about 35–40 seconds if their browser cannot send a departure message. Cursor updates use long polling in both LAN and online sessions, independently of project saves.

For participants outside your local network, double-click **start-online.cmd**. It downloads the tunnel tool on first use and prints a temporary HTTPS room link, username, and session password. Keep the launcher open and your PC awake. See [Online sharing](ONLINE-SHARING.md) for setup, student distribution, and troubleshooting.

Click **Share workshop** for this computer's local-network address and room link. Students on the same LAN open that link. Keep the Node process running. Allow Node.js on your **private network** in Windows Firewall if asked. Networks with client isolation may prevent students reaching the server.

Edits are transmitted as individual actions and serialized on the server. Each browser immediately sees its own edit, then receives server updates using Server-Sent Events. Different simultaneous edits are retained; for edits to the same property, the last accepted action wins. Reconnection retries unsaved actions while the page stays open. The interface displays save/connection status. Do not close a tab with unsaved edits.

Project replacement (import, clear, example, undo/redo) requires an unchanged server revision. A stale replacement is rejected rather than overwriting collaborators. Undo history is local to a browser and is cleared if another participant has changed the project since that undo entry. Playtest is private to each browser.

Projects persist in **data/<room>.json** after each accepted edit. Back up this folder or export JSON. An exported project includes all levels, definitions and placement notes, excluding temporary playtests. Font loading uses Google Fonts when available, with system-font fallbacks; all functional assets are local.

The regular **start-workshop.cmd** mode is a **trusted local classroom tool** with no authentication, TLS, or permissions. Anyone who can reach that server and knows a room link can edit it. Do not expose that mode directly to the public internet. Use **start-online.cmd** for a password-protected HTTPS tunnel instead. Its password grants editing access to all rooms. Use separate room links to organize student groups. The regular LAN server listens on `0.0.0.0`; online mode listens only on `127.0.0.1`.
